# Story 6.8 — Replacement-candidate surfacing on a sell, with re-concentration flags (FR48)

Status: done

## Story

As Guy,
I want the app, **when I sell (or a sell/stop trigger fires), to surface my watchlist candidates nearest to or inside their Buy zone** — each with its zone, its upside/downside and neutral re-concentration facts (already-held share, currency exposure) — and let me open the candidate's study,
so that selling triggers disciplined redeployment ("sell only for a better opportunity, stay invested") instead of a vague "what now?", while the app only ever states facts and never says "buy this one".

## Acceptance Criteria

1. **AC1 — The candidates read (app state, pure).** A new read `replacement_candidates(reference_currency)` builds, from the WATCHLIST (Story 4.1 order = position), one candidate per watch item: (a) the linked study resolved via the item's `study_id`, else `study_id_for_ticker` (the existing case-insensitive most-recent match — the 4.1 auto-link rule); (b) from `engine::build_snapshot(study)` ONCE per candidate (the `state/confront.rs:60` off-form precedent): the present-price **zone** (`risk_reward.present_price_zone`), the **distance above the buy zone** as a percentage (`(price − zones.buy_top) / buy_top`, exact `Decimal`, only when price > buy_top; inside the zone = distance zero-equivalent, flagged `in_buy_zone`), and the **U/D ratio** (`UpsideDownside::Ratio` — `Undefined`/`Unknown` render as absence, never 0); (c) the study's `native_currency`. **Ordering pinned (deterministic):** in-buy-zone first (watchlist position tiebreak), then ascending distance-above-buy-zone, then candidates whose zone/price/bounds are unavailable (« données insuffisantes »), then unlinked items (« aucune étude ») — an unlinked or data-less candidate is an HONEST row, never dropped. A held ticker appearing on the watchlist is listed like any other (its held-share fact appears via AC2).

2. **AC2 — The re-concentration facts (FR48 "flags", FR13-neutral).** Each candidate carries two OPTIONAL facts, both murmur-flagged with the SAME configured threshold band as 6.7 (`core::risk::concentration_flagged`, threshold − 10 floored at 0 — one threshold, one band, no new config): (a) **already-held share** — when the candidate's uppercased ticker is in `journal_diversification(...).rows`, its `share_pct` (« déjà détenu : N % du capital total »); (b) **currency exposure** — the share of the TOTAL invested capital already denominated in the candidate study's `native_currency`, from a NEW small read `journal_currency_exposure(reference_currency) -> Vec<(currency, share_pct: Option<Decimal>)>`: group ALL active holdings journal-wide by `effective_currency`, convert each bucket's invested at `latest_fx_rate` + `core::risk::fx::convert` (identity for the reference — the exact 6.6/6.7 rails, memoized lookups per the 6.7 review), divide by the same checked global; a missing pair absents the affected share (and the flag) with the pair named — **an absent fact never flags and never passes as zero**. SECTOR flags are OUT: no sector field exists anywhere in the data model (verified contract/persistence/ingestion) — record a GitHub issue at dev time («sector re-concentration needs a data source»), do NOT invent one.

3. **AC3 — Surfacing: after a sell and from a trigger (PRD Journey 4).** The candidates panel is a PORTFOLIO-LEVEL pushed-state panel (the 2.12 confirm-banner pattern — it must survive the sold row leaving the register on a whole-position sell): (a) it OPENS automatically after a successful sell — BOTH paths: the 4.7 trigger-panel sell (`on_sell_holding`) and the 6.3 ledger-form sell (`on_record_sell`), whole or partial — headed by the sold ticker (« Vente enregistrée : {t} — candidats de la liste de suivi ») and NEVER auto-opens on anything else; (b) the 4.7 trigger panel gains a fourth action « Candidats » that opens the same panel BEFORE deciding (sell-zone entry / stop breach are surfacing moments too); (c) « Fermer » dismisses it (session-only, the `holding_dismissed` transient pattern — no persistence); it also clears on journal switch/open (the 6.6 FX-panel re-render sites lesson: stale cross-journal state must not survive). While open, holdings/watchlist mutations re-sync it (the `sync_ledger_panel` precedent).

4. **AC4 — The panel UI (colour budget, posture).** Per candidate line: ticker · the zone stated in WORDS via the `Labels` zone nouns (the register precedent — no hue: §4 owns the zone colours) or « dans la zone d'achat » / « à N % au-dessus de la zone d'achat » · « H/B {ratio} » when the U/D is a ratio (absent otherwise — em-dash/nothing, never 0) · the currency + its exposure fact · the held-share fact when held · the murmur suffix on flagged facts (in words, ink only — the 6.7 « seuil approché ou atteint » pattern, threshold displayed via the LOCALE path, the 6.7 review lesson). Honest absences: « aucune étude » / « données insuffisantes » rows render their reason. Hand-off per candidate: **« Ouvrir l'étude »** (linked) → switch `current-screen = 0` + invoke the EXISTING `Studies.open-study` rail from Rust (`invoke_open_study` — reuse the whole open path: undo reset, push_form, study-open; do NOT re-implement); **« Études »** (unlinked) → switch to screen 0 only (the create form lives there; ticker prefill is deferred polish — see open questions). All copy neutral, posture-gated; **`@tr` floor (406) and MSG inventory (100) bumped by the exact new counts**; display strings built in Rust via `format_scaled` where numeric; no French prose baked into Rust data.

5. **AC5 — Invariants & scope pins.** `core::ssg`/method/goldens untouched; `core::risk` unchanged unless a pure helper is genuinely missing (none anticipated — `share_pct`/`concentration_flagged`/`convert` suffice); every FX multiply through `core::risk::fx::convert`, every conversion call site in a journal-wide consolidation-type read (grow the `core/src/risk/fx.rs` pin doc if `journal_currency_exposure` lands in a new module); 9-table schema FROZEN, NO migration, NO new dependency, NO contract change; watchlist writers unchanged; the 4.7 sell/raise-stop actions and the stop-priority rule untouched. Scope OUT (PRD-grounded): sector flags (no data — GitHub issue); Company Comparison side-by-side (**7.1**); discovery/screening (**7.3**); auto-writing « remplacé par Y » into any rationale (FR13 — the app never writes the user's rationale; the sell-rationale field IS the record, the Epic-8 interrogation seam — documented, not automated); create-form ticker prefill (polish, GitHub issue if wanted); provider work (**6.9**); buy execution / redeployment amounts.

6. **AC6 — Gates.** Tests (state, headless — the 6.7 suite's shape): ordering exact (an in-zone candidate before a nearer-but-outside one; two outside sorted by ascending relative distance; data-less then unlinked last; watchlist-position tiebreak); distance math exact against hand-computed `buy_top`; U/D `Undefined` → absent; held-share fact appears ONLY for a held candidate and flags per the band; `journal_currency_exposure` exact with two currencies + rates (shares sum to 100), missing pair → that currency's share absent AND named, never zero, never flagged; identity for reference-currency buckets (no self-rate lookup); unlinked/no-price candidates land in their honest buckets; sold-holdings excluded from exposure (position facts, 4.6/6.2 semantics); no-journal → empty/unavailable, never a zero state. fmt + clippy `-D` `--locked` + `test --workspace` (710 pass currently — grows) + `cargo deny` + smoke exit 124; `Cargo.lock`/`deny.toml`/pinned crates re-diffed EMPTY; posture floors bumped exactly.

### Design decisions (grounded, post-PR #97)
- **Panel is portfolio-LEVEL, not per-row** — a whole-position sell removes the row (`MSG_HOLDING_SOLD` path drops it from the register), so a per-row panel would vanish with its trigger. The 2.12 pushed-state banner pattern (`study-action-confirm-*`) is the shape; the dismiss stays session-only (4.7 `holding_dismissed` semantics, but a single panel flag + context ticker, not a per-id set).
- **One threshold, one band** — the FR48 flags reuse `concentration_threshold_pct` + `concentration_flagged` verbatim. A second knob would be a second majority definition; the PRD has one.
- **Distance is RELATIVE** (`(price − buy_top)/buy_top`) so candidates compare across price scales; displayed via the locale Percent path.
- **`build_snapshot` per candidate at panel build** — the watchlist already pays exactly this cost per refresh (`study_in_buy_zone` → `build_snapshot` per item, `wiring/watchlist.rs:32`); the panel builds on open/sell/sync, not on every register render.
- **An absent fact never flags** — a missing rate absents the currency share (named), `None` U/D absents the ratio; flags fire only on PRESENT shares (the 6.7 honesty rules).
- **Hand-off reuses the existing open rail via `invoke_open_study`** — the open path (reset_undo → push_form → view-state → `study-open`) must stay ONE code path; `current-screen` is the plain `in-out` int on the root window (`app.slint:53`, 0 = Études).
- **The « sold X → replaced by Y » record is the sell rationale** (6.3, first-class field) — the app documents the seam and never writes it (FR13).

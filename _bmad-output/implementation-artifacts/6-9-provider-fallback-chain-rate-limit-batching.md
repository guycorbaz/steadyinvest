# Story 6.9 — Provider fallback chain per field type + rate-limit batching (FR26, FR27)

Status: done

## Story

As Guy,
I want a **fallback chain per field type** (price, fundamentals, FX) — so a quota-hit or capability-limited provider fails over to the next one, with the **effective provider recorded** — and my watchlist/portfolio refreshes **paced within each provider's declared rate limits**,
so that one provider outage, quota or free-tier gap never blocks a refresh, and a batch refresh never burns through a quota — while every figure still says where it actually came from.

## Acceptance Criteria

1. **AC1 — Per-field-type fallback config (FR26; the 6.7 append-only pattern).** `AppConfig` gains three append-only `Option<String>` fields — `price_fallback_provider`, `fundamentals_fallback_provider`, `fx_fallback_provider` — each holding a provider WIRE name (validated: parses as a `ProviderChoice`, never `none`). The PRIMARY stays the existing global `preferred_provider` (FR26's "preferred provider" — unchanged). Accessors produce the **effective chain per field type**: `[primary]` + `[fallback]` when set, valid, **different from the primary**, and **capable of the field** — capability is a pinned static table (`supports(choice, field)`): Twelve Data does NOT serve fundamentals (its financial fields are `None` by design, story 7.4), EODHD serves all three, `None` serves nothing. An unset/damaged field falls back alone to "no fallback" (validate-before-trust, the `_or_default` rail). Internal shape = a `Vec` (generalizes beyond two providers later); the UI exposes primary + one fallback (two real adapters exist).

2. **AC2 — The worker fails over down the chain; the effective provider is RECORDED (FR26).** Each enqueue site resolves the field-type chain **with each member's own key** (`resolve_provider_key` per member — the keychain slots are per-provider already) and ships it in the request (`FetchRequest`/`FxRatesRequest` carry a chain, not a single provider). The worker tries members in order; **any `ProviderError` advances to the next member** (a `TickerNotFound` too — symbol coverage differs across providers); the LAST member's error is the surfaced one (the existing 3.5 `provider_failure_notice` mapping, unchanged). Recording, WITHOUT touching `contract`: (a) **cells** — `hash_of_dependencies` already flows through `dependency_digest(provider_tag, …)`; VERIFY the tag is a **readable prefix** (`"eodhd:…"`) of the stored digest string and make it so if it is only hashed in (the digest is an opaque `String` — reformatting its value is an app/ingestion change, NOT a contract change); (b) **FX rows** — `fx_rates.source` already stamps the wire name: stamp the EFFECTIVE member's wire, not the primary's; (c) **the user notice** — when the effective provider ≠ the primary, the refresh outcome notice names it (new posture-gated template « Récupéré via {p} (repli). » or equivalent), so a fallback is a visible event, never a silence.

3. **AC3 — Declared rate limits respected; batch fetches paced; quota retry-after honored (FR27).** Each adapter DECLARES its request pacing as a documented const (`min_request_interval()` on the ingestion `Provider` enum): Twelve Data free tier = 8 req/min → **7500 ms**; EODHD → **200 ms** (courtesy spacing; its quota is daily). The single worker thread keeps a last-request `Instant` per provider tag and **sleeps the remaining interval before each request** — an N-ticker watchlist/portfolio refresh (already enqueued as N per-ticker jobs) and the N-pair FX loop are thereby paced within the declared limits without changing the enqueue sites. On `ProviderError::Quota { retry_after_secs }`: wait `min(retry_after, 30 s)` and retry that member ONCE; a second quota (or a missing/oversized retry-after) advances the chain / surfaces `MSG_PROVIDER_QUOTA` as today. The pacing/retry DECISIONS are pure, unit-testable functions (`delay_before(now, last, interval)`, `quota_wait(retry_after)`-style) — NO sleep-based tests; the worker consumes them. Timing uses `Instant` (monotonic infra timing — ADD15 governs journal facts, not throttling). The `refresh_pending` latch and per-outcome marshalling stay untouched.

4. **AC4 — Réglages: the fallback pickers (FR63).** The provider panel gains three labelled rows — « Repli prix », « Repli fondamentaux », « Repli taux de change » — each a chip set (Aucun / EODHD / Twelve Data) persisted to the new config fields; picking the current primary is accepted at commit but neutralized by the accessor (chain dedups) — or refused with the existing chip disabled, dev's choice, documented. The fundamentals row's Twelve Data chip is DISABLED (capability table — the panel never offers an incapable fallback). Key management is unchanged (each provider keeps its own keychain slot; the key panel already exists per provider). All copy neutral, posture-gated; **`@tr` floor (430) and MSG inventory (100) bumped by the exact new counts**.

5. **AC5 — Invariants & scope pins.** `core`/*` untouched; `contract` UNTOUCHED (the digest-string reformat is app/ingestion-side; `Source` stays the bare enum); `persistence` schema frozen (9 tables), `fx_rates` writers' signatures unchanged (only the stamped source VALUE becomes the effective member); NO migration, NO new dependency (sleeps via `std::thread`/existing tokio; `Instant` is std); FR65 stays MANUAL-only (no background polling — pacing spaces user-initiated batches, it never schedules new ones); the 3.2 key rails and 3.5 failure notices unchanged in shape. Scope OUT (PRD-grounded): bulk/multi-ticker endpoints (EODHD `/eod-bulk-last-day` — a GitHub issue if wanted; per-ticker requests + pacing satisfy FR27's letter at personal scale); per-field-type PRIMARY providers (the primary stays global); persistent retry queues; provider health dashboards; any provider ADDITION (7.4 owns adapters).

6. **AC6 — Gates.** Tests: chain iteration — quota/network/not-found on member 1 lands member 2's result (FakeProvider-style doubles, the 3.x offline pattern); an incapable member is SKIPPED for fundamentals (twelvedata) but serves price/fx; the effective provider lands in the digest prefix (readable) and in `fx_rates.source` (effective ≠ primary case); the fallback notice fires only when effective ≠ primary; pacing math exact (`delay_before` boundaries: first request = no delay, elapsed ≥ interval = no delay, partial = exact remainder); quota retry decision (retry_after 5 → wait 5 s once; 3600 → capped/advance; None → advance); config round-trip + old-config-defaults + damaged-value fallback (the 6.7 config test shape); chain accessor dedups primary and drops incapable/invalid entries. fmt + clippy `-D` `--locked` + `test --workspace` (715 pass currently — grows) + `cargo deny` + smoke exit 124; `Cargo.lock`/`deny.toml`/`contract/`/`persistence/`/`core/`/`report/` re-diffed EMPTY (ingestion + app only); posture floors bumped exactly.

## Dev Notes

### Scope
- **In:** per-field-type fallback chains (primary + one fallback at the UI, `Vec` internally), capability filtering, per-member key resolution, worker failover, effective-provider recording (digest prefix + FX source + notice), declared per-provider pacing, quota retry-after (bounded, once), the Réglages pickers.
- **Out:** bulk endpoints; per-field primaries; background/scheduled fetches (FR65 manual-only); retry persistence; new adapters (7.4); provider health UI.

### Design decisions (grounded, post-PR #99)
- **NO `contract` change.** FR26's "effective provider recorded" is satisfied durably by (a) the provider-tagged dependency digest already stored per refreshed cell (`hash_of_dependencies` is an opaque `String` — formatting its value `"{tag}:{sha}"` is app/ingestion territory) and (b) `fx_rates.source` (the 6.5 rail — stamp the effective member). A `Provenance.provider` field was considered and REJECTED: the 5.3 journal envelope rejects unknown fields (`deny_unknown_fields`), so even an "additive" contract field creates an export/import compatibility cliff — out of all proportion to this story.
- **Failover on EVERY `ProviderError`** — including `TickerNotFound` (symbol coverage differs per provider) and key errors (a misconfigured member must not block the chain). The LAST error surfaces through the unchanged 3.5 notice mapping.
- **Capability is declared, not discovered** — Twelve Data structurally cannot serve fundamentals (7.4: financial fields `None` by design); a success-but-empty response would never trigger error-based failover, so the chain must skip incapable members up front.
- **Pacing lives in the ONE worker loop** (`spawn_fetch_worker`'s `while let Ok(job)`) — the single choke point every job serializes through; enqueue sites stay untouched (N per-ticker jobs remain the batch shape; pacing makes them quota-safe, which IS FR27's requirement).
- **Keys per member at enqueue** — the worker never talks to the keychain (thread + NFR-S1 discipline); `resolve_provider_key` already handles the env fallback. A keyed member with no key is dropped from the shipped chain at enqueue (with the primary-only no-key behaviour unchanged: the existing `MSG_PROVIDER_NO_KEY` guard fires when the PRIMARY lacks its key and no capable fallback remains).
- **Pure decisions, dumb loop** — `delay_before`/`quota_wait` are pure functions; the worker only sleeps what they return. No test ever sleeps.
- **`Instant`, not the journal clock** — throttling is infrastructure timing; ADD15 (injected clock) governs journal facts only. Document in place.

### Previous story intelligence (6.7/6.8 + reviews — directly applicable)
- **Append-only config discipline**: each field validates independently; accessors validate-before-trust; a half-specified pair must keep the entered half (6.7 review HIGH) — here each field stands alone, no pair coupling.
- **A failed/absent thing names itself**: a skipped chain member (no key, incapable) is a documented decision, not a silent drop — the notice names the effective provider on fallback; the LAST error surfaces honestly.
- **No unchecked assumptions about "recorded"**: VERIFY the digest tag is readable before claiming AC2(a) — if `dependency_digest` hashes the tag in, reformat the VALUE (unit-test the exact string shape).
- **Posture floors are exact counts** (probe trick in posture.rs history); French prose never baked into Rust data — the fallback notice is a registered MSG template, the chip labels are `@tr`.
- **Re-render/mirror rails**: new Prefs props mirror at startup (`main.rs`) + on commit (the `mirror_provider_prefs` / 6.7 `mirror_risk_settings` shape).
- **Rail-wide issues to not replicate**: #93 (drafts never re-seed — chips, not text fields, avoid it here); #95 (IO-error-vs-absence conflation — the chain surfaces the last REAL error, never a synthetic absence).

## Open questions (defaults chosen, non-blocking)
1. **Failover on `InvalidOrAbsentKey`/`Forbidden`?** Default: YES (a misconfigured member must not block the chain); the key-status notices still fire when the chain EXHAUSTS on them.
2. **Quota wait cap** — default 30 s, single retry per member; longer retry-afters advance the chain (a user-initiated refresh must not hang minutes).
3. **Pacing consts** — twelvedata 7500 ms (free 8/min), eodhd 200 ms (courtesy; daily quota): documented code consts, NOT config (declared limits are facts about providers).
4. **Picking the primary as its own fallback** — default: accepted at commit, neutralized by the accessor (dedup) — simplest honest behaviour; a disabled chip is fine too if cleaner in Slint.

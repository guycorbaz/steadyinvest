# Story 6.7 — Concentration check on total capital + configurable diversify-by-size table (FR45)

Status: done

## Story

As Guy,
I want the app to check **concentration against my total invested capital** — regardless of which bank or currency holds a position — and to classify my holdings by **company size (from sales) against a configurable diversify-by-size table**,
so that I can see, as neutral facts, whether one security is approaching a majority of my capital and how my actual size mix compares to my chosen targets, without the app ever telling me what to do about it.

## Acceptance Criteria

1. **AC1 — The concentration read: per-security share of TOTAL invested capital, journal-wide (FR45; PRD Journey 3 "regardless of which bank or currency holds it").** A new app read `journal_concentration(reference_currency)` aggregates every ACTIVE holding across ALL portfolios by security (ticker uppercased — the identity rule every write/import site already enforces): each holding's invested (`avg_cost × qty` via `core::risk::total_invested` on its single-position slice, or the existing bucket fold) is converted to the reference currency (`latest_fx_rate(pair, None)` + `core::risk::fx::convert`, identity for reference-currency holdings — the exact 6.6 rails), summed per ticker with checked arithmetic, and divided by the **global total invested** (the same denominator the 6.6 consolidation computes) via a **checked division in `core::risk`** (new pure helper — architecture pins concentration arithmetic to `core/src/risk/`, line 626). Output per ticker: `(ticker, invested_ref: Option<Decimal>, share_pct: Option<Decimal>, missing_pairs)`. A missing rate absents the affected ticker's converted figure AND the global denominator honestly (named pairs, « taux manquant EUR → CHF » style) — never a partial sum passed off as a share, never a silent inversion. Overflow/None anywhere → the affected figure is ABSENT, never wrong.

2. **AC2 — The configured majority-share threshold; the warning is a neutral murmur.** `AppConfig` (app-config JSON, `app/src/config.rs` — the `default_trailing_stop_pct` precedent, ADD7: NOT the journal, NO migration, `#[serde(default)]` append-only) gains `concentration_threshold_pct: Option<String>` (default **"50"** — a majority share; validated like the trailing-stop pct: positive, < 100, exact decimal). The Portefeuille concentration block marks a security whose share is **within 10 points of, or above, the threshold** (FR45 "warns NEAR a configured majority share" — default: murmur from 40 %): a neutral marker + posture-gated message naming the fact (« X : N % du capital investi (seuil : S %) »), never an instruction, never a verb from the banned list, no colour spend (ink/glyph only — the zones own the hues).

3. **AC3 — The diversify-by-size classification (change-request_guy.md table; architecture line 334).** `AppConfig` gains a size table: two sales boundaries (`size_small_max`, `size_medium_max` — defaults **1000000000** and **10000000000**, i.e. $1B/$10B in the CR) and three target percentages (`size_target_small/medium/large_pct` — defaults **"25"/"50"/"25"**), all `Option<String>` exact-decimal-validated (boundaries positive & small < medium; targets positive, ≤ 100 — the three need NOT sum to 100, they are Guy's targets, not a partition we enforce). A new app read `journal_size_mix(reference_currency)` classifies each ACTIVE held security: ticker → most-recent study (`study_id_for_ticker`, the existing join at `state/holdings.rs:310`) → **latest year whose `sales.value` is Some** (walk `study.years` reversed app-side — do NOT call `core::normalize` here; the engine path stays untouched) → sales converted to the reference currency at `latest_fx_rate` (study `native_currency` → reference; identity when equal) → compared to the boundaries → Small/Medium/Large (`core::risk::SizeClass`, a new pure `size_class(sales, small_max, medium_max)` in `core/src/risk/`). Per class: Σ invested (converted) / global invested = actual %, shown against the target %. A security with **no study, no sales value, or a missing rate is « non classé » with its reason named** — an honest bucket in the mix, never dropped, never guessed. The CR's "anticipated growth rate" column is **informational display only** (static `@tr` strings in the settings table: « > 12 % » / « 7 – 12 % » / « 5 – 7 % ») — NOT config, NOT compared against anything (comparison is 7.2 Portfolio Health Review territory).

4. **AC4 — Portefeuille UI: the « Concentration » block (FR13-neutral).** Under the 6.6 consolidation block (`portfolio.slint`, after ~line 193 — the journal-wide risk-facts zone), a new block shows: (a) per-security share lines, largest first (share % of total invested + the converted amount), the threshold murmur marker on qualifying lines, honest absences (« indisponible : taux manquant … »); (b) the size-mix lines — one per class: « Small — N % (cible 25 %) » plus the « non classé » line with count when non-empty; (c) the same rates-footnote discipline as 6.6 where conversion happened (reuse the consolidation's `rates_used` dedup pattern). The block hides when there are no active holdings. Re-rendered by `refresh_holdings` (every holdings/ledger/FX mutation already flows through it — 6.6 review lesson: BOTH FX mutation paths re-render) AND when the threshold/table/reference-currency settings change. All copy neutral & posture-gated; **`@tr` floor (366) and MSG inventory (98) bumped by the exact new counts**; display strings built in Rust via the locale path (`format_scaled`), French prose never baked into Rust data (6.6 review lesson).

5. **AC5 — Réglages: the « Diversification par taille » panel.** A new settings panel (settings.slint, next to « Seuil suiveur par défaut » ~line 415 — the existing risk-threshold precedent) edits: the concentration threshold %, the two sales boundaries, the three target %s — each field validated on commit (invalid → posture-gated refusal message, value NOT clobbered — the 2.2 refusal-keeps-input rule), persisted to app-config, and pushed so the Portefeuille block re-renders on the next refresh. The panel states plainly (a `@tr` caption) that boundaries are compared against study sales **converted to the reference currency** and use the same unit as entered in studies. Defaults render when unset (config `#[serde(default)]` + `_or_default()` accessors, the `reference_currency_or_default` pattern).

6. **AC6 — Invariants & scope pins.** `core::ssg`/method/goldens/fingerprint untouched; the 6.2 per-currency CaR reads and 6.6 consolidation unchanged; `fx_rates` writers unchanged; every FX multiplication still goes through `core::risk::fx::convert` and every conversion call site lives in a journal-wide consolidation-type read (the FR28 structural rule — 6.6's "exactly two call sites" pin grows to the enumerated consolidation reads, documented in place). Scope OUT (PRD-grounded): sector/currency re-concentration flags and replacement candidates (FR48 = **6.8**); per-bank concentration (FR45 is against TOTAL capital); rate-staleness thresholds (#90); provider fallback/batching (**6.9**); Portfolio Health Review roll-up & growth-rate comparison (**7.2**); no journal-DB settings table (the 9-table schema stays frozen); NO migration, NO new dependency, NO contract/persistence schema change.

7. **AC7 — Gates.** Tests: two banks × two currencies — one ticker held at BOTH banks aggregates into ONE share line (the FR45 point); share math exact against hand-computed values; threshold murmur appears at threshold−10 and above, absent below; a missing rate absents that ticker's share AND names the pair (and the denominator refuses honestly); size classification hits Small/Medium/Large boundaries exactly (boundary value itself → pin which side, document it); a held ticker with no study / no sales / missing rate lands in « non classé » with the right reason; config round-trips (set → reload → same values) and rejects invalid input without clobbering; checked-overflow absents rather than corrupts; sold holdings stay EXCLUDED (position risk semantics, unchanged 4.6/6.2). fmt + clippy `-D` + `test --workspace` (686 currently — grows) + `cargo deny` + smoke exit 124; `Cargo.lock`/`deny.toml` byte-identical; posture floors bumped exactly.

### Design decisions (grounded, post-PR #92)
- **App-side orchestration, core-side arithmetic** (the 6.2/6.5/6.6 split): grouping/joins in `app`; the division, classification and every FX multiply in `core::risk` (`share_pct`, `size_class`, `fx::convert`); every sum `checked_add`.
- **Identity = uppercased ticker** — the allow-list uppercases every write/import site (6.6 review note), so journal-wide grouping by uppercased ticker is sound; one security held at two banks is ONE concentration line (the whole point of FR45).
- **Denominator = the 6.6 global invested.** Extract the global-invested computation from `journal_capital_at_risk_consolidation` into a shared helper rather than re-deriving it (extract, don't duplicate — the `car_buckets_by_currency` precedent). Any missing pair that absents the 6.6 global absents the concentration denominator identically (one honesty, one code path).
- **"Warns near"** pinned as: murmur when `share ≥ threshold − 10 points` (default threshold 50 → murmur from 40 %). Deliberate default, revisit with Guy if he wants the band configurable.
- **Sales unit honesty:** boundaries are plain configured decimals compared against the study's stored sales value converted to the reference currency. The app does NOT know whether Guy types sales in units or millions — that's exactly why the CR makes the table configurable; the settings caption states the convention. Default boundaries assume absolute values ($1B/$10B).
- **Sales lookup stays app-side and raw** (`study.years` reversed, first `sales.value.is_some()`): calling `core::normalize` here would drag the engine into a portfolio read and risk the method surface; the raw latest entered sales figure IS the honest classification input. Only the live `value` is read (never `pending`).
- **Sold holdings excluded** — concentration and size mix are position facts (same read family as CaR, unchanged 4.6/6.2 semantics).
- **Targets don't need to sum to 100** — they are Guy's per-class ceilings/anchors from the CR, not a partition; the panel never auto-balances.
- **No verdict language:** actual vs target is displayed side by side; « surpondéré »/« sous-pondéré » style judgments are banned-verb-adjacent — the numbers speak (FR13).

## 2. What went well

1. **The seam-verification spike (Epic-2 action B3) paid for itself many times over.** `seam_check.rs` (Spike-D) proved the stale-murmur, the `✓→?` divergent-edit demotion, and the verdict degradation *before* any reconciliation story. As a result, 3.3/3.4/3.5 built on **proven** rails — 3.5 was literally "set the flag the display already renders", and the verdict-degradation tests just drove the existing wiring through the production path. De-risking up front turned three risky stories into confident compositions.

2. **Strict crate discipline kept the method untouchable.** Only Story 3.4 touched `contract`, and it was a single additive `#[serde(default)] Cell.pending` field — **no `SCHEMA_VERSION` bump, no migration, no `v2.db`** (the Story-2.2 precedent), with the byte-pinned corpus re-captured per the documented convention. The method fingerprint / golden / determinism / frozen `v1.db` gates re-diffed clean across all six stories. The "data shape grows, the method does not" line held.

3. **The 3-layer adversarial review caught a real bug on every code-touching story** — N/A-accepted cells silently refilled (3.3 HIGH, a regression inherited from 3.1), the stale resolve-controls UI seam (3.4), the stale-forever + phantom-write pair (3.5), and the validate-empty edge (3.6). None were caught by the (green) test suites; the review is earning its keep, exactly as Epic-2 action B8 predicted.

4. **Security-by-construction held under pressure (NFR-S1).** The api_token lives in the request URL; 3.2's `reqwest::Error::without_url()` fix and 3.5's deliberate choice of **static** cause notices (no `{cause}` raw-error interpolation) mean there is *no code path* for the token to reach a user banner. Reviewers verified this explicitly.

5. **"Compose, don't rebuild" recognised at the capstone.** Story 3.6 reused six prior rails (reopen, unlock-all, refresh, reconcile, stale, extend-history) and added exactly one new thing — the `revalidate` change-summary. Naming it as glue-plus-one-piece kept the last story bounded and clean.

6. **The FR13 banned-verb posture gate is load-bearing, not ceremony.** It caught "Garder" (3.4) before it shipped; every new neutral notice passed by construction.

## 3. Challenges & growth areas

1. **Idempotency churn was the recurring trap of the whole epic.** It surfaced in *three* different forms: timestamp churn on an unchanged provider re-stamp (3.3), pending-provenance churn on a repeated divergence (3.4), and an unconditional journal write on a no-op stale-flag (3.5). The root cause is the same each time: `mutate_study`/`mutate_cell` *persist unconditionally* — only the **undo** step is guarded by `before != study`, not the SQLite write. Every new rail had to learn (often in review) to add a value-equality / no-op pre-check before the mutation, especially because the journal lives on a Synology-synced disk. **This is the standing lesson to codify.**

2. **The on-display GO/NO-GO residuals piled up (Epic-2 action B8 partially slipped).** Every UI-visible story (3.3 freshness reveal, 3.4 reconcile controls, 3.5 stale degradation, 3.6 change summary) ships with a "manual on-display GO/NO-GO — Guy" residual, and the batch has not yet been walked on a real display. The logic is fully headless-proven, but the *perceptual* half of B8 ("human-on-display per UI behaviour") has accumulated rather than kept pace. Risk: visual regressions stay unverified, and Epic 4 adds more UI on top.

3. **The free-tier EODHD plan blocks live fundamentals validation.** Guy's key is valid but the free plan 403s `/fundamentals` (discovered in 3.2). So every fundamentals-path GO/NO-GO must use the `demo` key / fixtures, never Guy's real data. The paid-plan-vs-other-provider decision is deferred — and it directly gates real end-to-end validation of Epic 4's per-holding price refresh.

4. **Provenance digests (Epic-2 action B4 / issue #21) were only half-taken.** 3.1 gave provider cells a real SHA-256 dependency digest, but reconciliation (3.4) detects divergence by **`Money` value equality**, not by digest — which is simpler and correct, so B4's "detect divergence by digest" path was quietly dropped in favour of value equality. Manual leaves still carry the `"manual"` sentinel. Not a problem, but the B4 intent was superseded rather than completed; #21 stays open.

## 8. Key takeaways

1. **De-risk the seams before you build on them** — the Spike-D investment (B3) is the single biggest reason this epic was smooth. Repeat the pattern: **Epic 4 opens with the schema-migration story.**
2. **`mutate_*` persists unconditionally — guard every new rail against no-op writes** (the idempotency-churn class, seen three times). Codified as C4.
3. **3-layer review + headless tests are complementary, not redundant** — the review caught a real bug every story that the green tests missed; keep it the default.
4. **Additive contract changes keep the method frozen** — the `Cell.pending` field proved you can grow the data shape with zero method/migration impact (serde-default + corpus-pin re-capture).
5. **The on-display half of verification drifts under momentum** — make it a gated batch (C1), not a per-story afterthought, so it doesn't accumulate into Epic 4.

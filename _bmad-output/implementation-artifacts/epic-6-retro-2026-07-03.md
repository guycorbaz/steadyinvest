## 1. What went well

1. **One honesty doctrine, compounding.** 6.5/6.6 established the absence rules — *absent, never wrong; absent, never zero; every refusal names itself; a missing pair is named, never inverted; an IO failure is « indisponible », never an empty-looking zero state* — and every later story INHERITED them as explicit review criteria. The 6.7/6.8/6.9 reviews each caught honesty-class violations (misattributed missing pairs, a lying « Vente enregistrée » header, a silent fallback) precisely because the doctrine was written down and re-applied. The rules now read like a project-level contract.
2. **Outline-only stories refined one at a time worked.** Epic 6 entered with story OUTLINES only (the epic-5 E4 concern). The per-story "ultimate context" creation — verified `file:line` paths, previous-story intelligence, pinned scope, defaults for open questions — turned each outline into a dev-ready spec without a big up-front refinement phase. Documented deviations (6.7's self-consistent denominator; 6.9's no-contract-change decision) were judged by the Acceptance Auditor as intent-honoring.
3. **Structural pins held under pressure.** FR28's "conversion only at consolidation points" grew from *zero* convert call sites (6.5) to an enumerated, auditable set (6.6 roll-up, 6.7 diversification, 6.8 exposure) with the pin doc growing at each step. The append-only `AppConfig` rail absorbed ~15 new fields with zero migrations. The 6.9 decision to REJECT a `Provenance.provider` contract field (the 5.3 `deny_unknown_fields` export cliff) and record the effective provider in the digest STRING instead is the epic's best example of the pins doing their job as design inputs.
4. **The 3-layer review keeps catching what green tests cannot.** 6.7: a half-specified size table silently replaced by defaults after a *reported success*. 6.8: the panel asserting a sale that never happened. 6.9: the silent-fallback CRITICAL, the incapable-primary blind spot the code itself documented but only half-guarded, an F4 regression. None of these fail a test until the review writes one.
5. **Reuse discipline stayed real.** `car_buckets_by_currency` (6.2) seeded 6.6, 6.7 AND 6.8's reads; `build_snapshot` (via the 5.6 relocation) served the 6.8 candidates exactly as it serves the form, the PDF and confront; the one study-open rail was *invoked*, never copied, by the 6.8 hand-off.

## 2. What was challenging

1. **A new defect family emerged: state keyed off the wrong discriminator.** 6.8's header keyed "sold" off a non-empty context string; 6.9's fallback event keyed off chain *position* instead of provider *identity*. Same shape, two stories in a row — position/order/emptiness used as a proxy for a semantic fact. This needs a named checklist entry (see F3).
2. **The F4 notice-slot rule regressed** (6.9 review) after being deliberately guarded in 4.4 and re-honored in 6.8 — conventions that live only in old review notes get re-broken; they need to live where the code is (comments at the notice sites now name the rule).
3. **On-display verification debt re-accrued for the third epic straight** (epic-5 E1 was a *standing gate* and still slipped). Epic 6 added ~10 unwalked UI surfaces: the multi-portfolio selector, the currency picker, the ledger + dividend forms, the FX panel, the consolidation/concentration/size-mix blocks, the replacement-candidates panel, the fallback rows. The sandbox cannot walk them; only Guy's display can.
4. **The issue backlog grew again: ~19 → 28 open** (nine new this epic, #93–#101). E2 has slipped across three retros. Three of the new ones are RAIL-WIDE classes (#93 drafts never re-seed, #94 study mutations never re-render holdings surfaces, #95 IO-error-vs-absence conflation) that keep generating per-story defers — fixing each rail once would retire a whole recurring class.
5. **Two live paths remain headless-proven only:** the 6.9 pacing/fallback against real EODHD/Twelve Data endpoints (quota behaviour, retry-after values — #80 notes `retry_after_secs` is never populated by the adapters!), and the epic-5 carried rfd picker. #70 (cross-provider ticker conventions) now directly weakens the 6.9 fallback: a ticker that works on EODHD (`NESN.SW`) may 404 on Twelve Data (`NESN`), making failover LOOK like coverage failover when it is symbol translation.

## 7. Key takeaways

1. **Write doctrines down and reviews compound them** — the absence-honesty rules became enforceable review criteria; every story got safer as the epic advanced. Do the same NOW for the discriminator rule (F3).
2. **Pins are design inputs, not constraints** — the no-contract-change decision (6.9) produced a *better* design (readable digest) than the obvious field would have. The 5.3 `deny_unknown_fields` cliff is now a named hazard for any future contract-field temptation.
3. **A standing gate that isn't scheduled is a wish** — E1/E2 slipped again; F1/F2 are now blocking. The fix is calendar-shaped, not process-shaped.
4. **Rail-wide issues deserve rail-wide fixes** — three recurring defer-classes (#93/#94/#95) each generated findings in multiple stories; one chore each retires the class (F4 does #94).
5. **Zero migrations across a data-heavy epic** validates the v1 hybrid model — the normalized tables + append-only config absorbed multi-currency, the ledger, FX and the whole risk overlay untouched.
6. **The surprise class keeps moving** (schema → I/O → honesty → discriminators) — the durable lesson is the *habit* (read first, name the class, checklist it), not any one checklist.

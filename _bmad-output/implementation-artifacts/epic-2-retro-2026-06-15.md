## 2. What Went Well

### 2.1 Three reusable rails absorbed later stories almost for free
- **The confirm-before-act overlay** (built first in 2.5) was reused by 2.6 (traceability), 2.9 (scenario compare) and 2.12 (dashboard delete) — one primitive, four consumers.
- **The `mutate_*` rail** (`mutate_cell`/`mutate_judgment`/`mutate_study`: validate → re-read → mutate → `put_study` → re-push) absorbed undo/redo (2.9), rationale capture (2.10) and extend-history (2.11) with no new mechanism.
- **Single construction path** `StudySnapshot::new` once per frame (2.6) = coherence by construction; never two numbers from two computations. Every later story (2.7 plausibility, 2.8 drag, 2.9 scenario) depended on it.

### 2.2 The latency NFR was solved by architecture, not optimization
The chart (2.8) does **live preview on an unsaved `Study` clone and persists once on release**, never routing each `moved` through `push_form`+`put_study`. Combined with Spike B's measured 40–60 µs recompute, the <100 ms budget holds with ~3 orders of magnitude of headroom. The "clone-before-move off `CanonicalFinancials`" pattern (2.7 findings, 2.8 series) avoids a second `normalize` and any frame drift.

### 2.3 The 3-layer adversarial review is demonstrably higher-yield
Introduced at 2.8 and used through 2.13, the Blind Hunter + Edge Case Hunter + Acceptance Auditor structure consistently surfaced the highest-severity issues at **degenerate/empty states** that headless tests and single-pass review missed:
- 2.12 — controls vanished when the active view curated to empty (archived studies became unreachable) — **HIGH**.
- 2.8 — zero-movement click rewrote the forecast; refused commit left a phantom unsaved line — **2× P-High**.
- 2.9 — undo/redo while the compare overlay was open corrupted the baseline — **P-High**; no-op edit recorded a phantom undo step.

### 2.4 Trust-by-construction held through the UI layer
The Epic 1 invariants survived the move to rendering: verdict integrity gated on cell review × freshness (2.6), the verdict surface never says something it shouldn't (caught: Withheld wrongly showing a provenance caption, numbers frozen while the bar recoloured), and the read-only demo (2.13) achieved read-only **by construction** via `current_study==None` — every edit callback already early-returns, so zero new gating code.

### 2.5 Epic 1 conventions paid off again
Previous-story-intelligence propagation, interpretations-to-GitHub-issues (never inline debt), and crate-local posture tests all carried into Epic 2 and measurably reduced findings. The verify-engine UI (2.13) **replayed** Epic 1's golden harness rather than redefining it — exactly the seam Epic 1 built for this story.

## 3. What Was Challenging (recurring patterns)

### 3.1 Soft-lock symmetry — the most-repeated correctness trap
Every new write path that forgot the `MSG_SOFT_LOCKED` guard was a bug: 2.5 (`set_not_available` blanked a ✓ cell), 2.8 (vertical drag stolen / not guarded), 2.9 (Ctrl+Z swallowed by the locked-cell catch-all). **Standing lesson:** every write path touching a cell needs the same guard; review must check for it explicitly.

### 3.2 Transient flags / state not reset on study open-close
Cousin of 3.1: `judgment-dragging` could leak and trap the form unscrollable (2.8), compare state survived a reopen (2.9), demo folds/undo weren't reset (2.13). **Standing lesson:** reset every transient flag on study open and close.

### 3.3 File-List ⇄ git drift recurred despite issue #18
Issue #18 was filed in the Epic 1 retro (action item A2) for exactly this, but the underlying story-automator QA step was never fixed — so 2.6 marked `[x]` for tests that did not exist, and the File List repeatedly omitted the automator log. The review caught it every time, but it is a process gap, not a code gap. **Decision (see §7):** fix the automator at the source before Epic 3.

### 3.4 Slint friction & dead-code-under-clippy (minor, omnipresent)
- Reserved attached-property names (`row` in 2.2/2.4, `z` in 2.6) caused `Cannot override property` compile failures and renames.
- `@children`/element ids illegal inside conditionals (2.3).
- `clippy --all-targets` builds the binary without `cfg(test)`, so any adapter fn not wired into a production callback fails `-D warnings` (2.6 `snapshot_for`, 2.7). Forced "wire it into the form/a callback, don't leave it test-only."
- Posture-floor over-bumping recurred (2.3, 2.5, 2.8, 2.10, 2.13) — minor correction each time.

### 3.5 Visual verification remains a documented partial
The Wayland sandbox blocks screenshots and AT-SPI, so pixel-level click-through is a "documented partial (human/AT-SPI)" across the whole epic. Only 2.8 got real human-on-display verification — and it caught real bugs headless could not (Flickable stealing the drag, trend-line semantics, contrast). This confirms the Epic 1 prediction that the DoD's visual-verification rule is load-bearing for UI stories.

## 5. Key Insights (carry into Epic 3)

1. **A new write path is a soft-lock liability.** Every cell-touching write needs the `MSG_SOFT_LOCKED` guard; make it an explicit review checklist item.
2. **Reset transient flags on study open/close** — the whole class of stuck-state bugs (drag flag, compare state, demo state) traces to this.
3. **Build the seam, but exercise it before you depend on it.** Epic 2 built several Epic 3 seams (stale-murmur, provider-divergent `✓→?`, provenance sentinels, empty `QuarterlyObservations`) that are *only* triggered by test fixtures today. Epic 3's first consumer must verify they actually render/behave correctly.
4. **Filing an issue ≠ fixing the gap.** A2/#18 proves a tracked-but-unfixed process gap just keeps costing review attention. Fix recurring process findings at the source.
5. **3-layer adversarial review earns its cost on UI work** — it found the epic's highest-severity bugs at degenerate states. Keep it as the default for Epic 3.
6. **Visual verification is load-bearing and currently sandbox-limited** — plan human-on-display checks for every Epic 3 UI-visible behaviour (refresh, stale flagging, reconciliation recolour).

## 10. Key Takeaways

1. **Reusable rails are the multiplier.** The confirm overlay, the `mutate_*` rail and the single construction path absorbed half the epic's later stories almost for free — keep investing in choke-point primitives.
2. **The two recurring bug classes are soft-lock symmetry and unreset transient flags** — now codified as a review checklist (B7).
3. **A tracked-but-unfixed process gap keeps costing** — A2/#18 is the proof; fix recurring findings at the source (B2).
4. **Seams must be exercised before they're trusted** — Epic 3 opens with a spike that turns the fixture-only stale/divergence seams into verified behaviour (B3).
5. **3-layer adversarial review + human-on-display verification** are the quality pair that catches what headless cannot — make both the Epic 3 default (B8).

## 2. What Went Well

### 2.1 The exact-decimal, no-float architecture is validated end to end
Spike C measured `rust_decimal` fractional `powd` error at ≤ 1e-27 (18 orders of magnitude inside the asserted 1e-9 bound); integer-power projections are exact. Spike B measured judgment-line drag recompute at 40–60 µs typical (235 µs max) — the <100 ms budget has ~3 orders of headroom, **in exact Decimal, not floats**. There is no performance excuse to ever leave the exact decision chain. The "Slint-only, no egui/web" decision is locked by evidence.

### 2.2 Pinned-constant determinism gates became the project's spine
The SHA-256-over-normalized-decimals pattern (determinism hash → method fingerprint → Spike-C digest → golden gate → persistence JSON snapshot → frozen corpus) was reused six times and caught real problems each time it was tightened (Debug-based serialization instability in 1.2, a no-op CI `--exact` filter in 1.1, missing `--locked` flags). Cross-OS determinism holds **by construction** (pure-Rust `rust_decimal`) even with Linux-only CI.

### 2.3 Exact-by-construction metamorphic testing
The discipline invented in Spike C (build inputs so true results are exact by construction; round-trip checks instead of hand-typed transcendental constants) carried through 1.7 (split-invariance with zero tolerance) and 1.8 (scale-homogeneity with terminating-quotient strategies). When the predicted precision trap fired in 1.8 (`(k·a)·p ≠ k·(a·p)` at 28 significant digits), the team constrained the construction instead of adding tolerance — exactly right: tolerance would have hidden real bugs.

### 2.4 The golden oracle harness is honest
11 hand-computed fixtures with documented independent provenance, an anti-circularity rule (never paste engine output back as expected), serde-strict parsing (`deny_unknown_fields`, presence-enforced nullable fields), embedded negative controls proving the gate cannot silently pass, and a drift test binding `core/tests/golden/` to `app/assets/golden/`. Notably, fixture g09 was **corrected against the engine** after hand re-derivation — the engine was right; the process worked as designed.

### 2.5 Interpretations go to GitHub issues, never inline debt
Every spec-underspecified decision was recorded as a GitHub issue queued for the next `METHOD_VERSION` bump (#12, #13, #15, #16, #17) instead of silent code choices or markdown notes. This kept the method spec a clean versioned oracle while leaving a complete audit trail.

### 2.6 Story-to-story knowledge transfer worked
The "Previous story intelligence" section in each story file demonstrably propagated lessons: `--locked` gates, clippy `--all-targets` coverage of test code, self-explaining assert messages, crate-local posture tests, the validate-before-mutate lesson from 1.10's review applied in 1.11's snapshot constructor. Velocity visibly improved across the epic — later, larger stories (1.9–1.11) landed with fewer review findings per unit of scope.

### 2.7 Trust invariants are structural, not procedural
`FullVerdict` is unconstructible outside `core` (proven by a `compile_fail` doctest); verdict and staleness derive from one immutable snapshot, so the forbidden frame ("fresh verdict over a stale input") is unrepresentable. Invariant 2b lives in `contract` so Epic 3's reconciliation branches onto the same rail with zero new mechanism.

## 3. What Was Challenging

### 3.1 The architecture document drifted from reality (recurring)
Live validation contradicted several architecture.md claims:
- **MSRV**: claimed 1.88; actual is **1.96** (Slint 1.16 transitive deps + libsqlite3-sys 0.38).
- **`normalize` placement**: the architecture tree puts it under `ingestion/src/`; it was built in `core/src/normalize/` (the epics file deliberately superseded the tree — documented variance, but the tree still says the wrong thing).
- **keyring crate**: the assumed `keyring 4.0` pin is wrong (pulls a massive turso/db-keystore stack) — issue #5, deferred to Story 3.2.
- **reqwest TLS**: `rustls-tls` feature renamed; default provider needs cmake — deferred to Story 3.1.
- **CI matrix**: architecture describes 3-OS gates; CI has been Linux-only since 2026-06-09.

None of these blocked work (each story's Dev Notes corrected course), but every story paid a small tax re-stating "the architecture's 1.88 is stale". **The doc should be fixed once instead.**

### 3.2 Story-record staleness after the QA automation pass (recurring review finding)
In 5 of the last 6 stories (1.6, 1.7, 1.8, 1.9, 1.10, 1.11), the review's only Medium finding was the same: the QA-automation step added test files (`*_qa_e2e.rs`, `test-summary.md`) that never made it into the story's File List / test counts. The reviews caught it every time, but it is the single most repeated finding of the epic — a process gap, not a code gap.

### 3.3 The spec is deliberately thin → interpretation overhead
Stories 1.7–1.11 each had to make and file defensible interpretations (split-break quantification, trend window, CAGR endpoints, Withheld/Provisional split, etc.). The issue-per-interpretation discipline contained the risk, but the volume (#12, #13 with twelve items, #15, #16, #17) signals that the next `METHOD_VERSION` bump should consolidate them back into the spec.

### 3.4 Headless limits on spike verdicts
Spikes A and B required Guy's on-display perceptual confirmation; CI can only prove gates-green. This is inherent, but Epic 2 (UI-heavy) will hit it constantly — the Definition of Done's "launch the app and visually verify" rule becomes load-bearing.

## 5. Key Insights (carry into Epic 2)

1. **Constrain the construction, never the assertion.** Zero-tolerance `assert_eq!` plus exact-by-construction inputs beats tolerances everywhere it's achievable.
2. **Snapshot gates need canonical serialization** (never `Debug`, always `Decimal::normalize`) and byte-verified CI commands (`--locked`, full test paths).
3. **Validate before mutating** — 1.10's `Journal::open` mutated a foreign file before checking identity; the fix pattern (read identity first) should be standard for every file/state-touching API in Epic 2.
4. **Value equality ≠ serialization equality** for `Money` (`"3.0"` == `"3"` as values, ≠ as bytes). Anything hashing or byte-comparing serialized data must normalize first; scale-preservation tests must compare stored payload strings.
5. **Fixtures are strict, user data is tolerant** — `deny_unknown_fields` for oracles, `serde(default)` + unknown-field tolerance for journal data. Never mix the rails.
6. **Spec ↔ code drift is real** (the 15-vs-16 banned-verb mismatch) — cross-link prose lists to code constants with tests.

## 1. What went well

1. **De-risking the seam first (D5) paid off exactly as planned.** Story 5.2 built the versioned envelope — `contract::export::StudyExport` = data-contract JSON + `schema_version` + SHA-256 integrity hash + a per-study version gate — and 5.3 reused it **verbatim** to scale to the whole journal (`JournalSnapshot`/`JournalExport` reusing `sha256_hex`), then 5.4 leaned on the same integrity discipline for restore. One integrity contract, exercised before the stories that built on it, three stories deep.
2. **The 3-layer adversarial review caught a real bug on every story — including the epic's only CRITICAL.** 5.4's `restore` had a **self-restore data-loss bug**: `fs::copy(p, p)` truncates the file to zero, so restoring a journal onto itself would wipe it — caught by the review, fixed with a same-path guard + an atomic temp-then-rename swap + TOCTOU re-validation. 5.1's review caught a **design-level desync** (a price-cache write bumping `logical_version` would break export-identity = exported-content). 5.5 took 12 patches incl. WAL-in-a-sync-folder. None were caught by the green test suites.
3. **The provider decision (D2/C2) — open since Epic 3 — was finally resolved cleanly.** Guy chose to **add Twelve Data** rather than pay EODHD; the price adapter (story 7-4, pulled forward from Epic 7) shipped and unblocked 5.1's confront cache, giving price **redundancy** without a paid plan. The long-standing gate is closed; both providers are live.
4. **The method stayed frozen; the schema barely moved.** `core::ssg` fingerprint/golden/determinism re-diffed clean across all six stories. The whole epic needed **one** migration (v4→v5 for the `price_history` cache); everything else was additive at the `app`/`persistence`/`report` layer. `contract::SCHEMA_VERSION` never changed.
5. **The "single construction path" invariant was *strengthened* under pressure.** 5.6 relocated `build_frame` from `app` into `report::form` (re-exported by `app`) so the live form and the PDF share **one** construction — drift became *structurally impossible*, stronger than the pin test it replaced. An architectural cleanup delivered as a side-effect of a feature.
6. **Dependency hygiene under `cargo deny` turned a trap into a clean pivot.** 5.6's PDF backend: printpdf 0.7 tripped a `lopdf` parse-advisory (unreachable — we only write) and 0.9 pulled a heavy tree; the gate steered the choice to `pdf-writer` (write-only, 4 tiny leaves, deny-green) with **no advisory exception**. Every new dep this epic was checked; `deny.toml` was never edited.
7. **Read-only and identity discipline held.** Confront (5.1) is strictly read-only of journal identity; the price cache is the *only* writer that doesn't bump `logical_version` (it's excluded from the export snapshot). Backup/restore operates on the raw `.db`, never the JSON envelope. Each boundary was deliberate and reviewed.

## 2. What was challenging

1. **On-display GO/NO-GO accrues *again* — the perceptual-verification debt is structural.** D1's batch (3.3–3.6 + 4.1–4.7) was cleared on 2026-06-29, but 5.1–5.6 immediately added a **new wave**: the confront overlay, four path-based Réglages panels (5.2/5.3/5.4/5.5), the **rfd native picker whose live dialog is UNVERIFIED** (the sandbox has no `xdg-desktop-portal`), and the PDF (eyeballed via a rasterized demo, but not the in-app action). The debt re-accumulates every epic.
2. **The native file picker (5.5) cannot be verified headless.** `rfd` + `xdg-portal` needs a desktop portal the CI/sandbox lacks; the dialog is exercised only by construction. A genuine gap that only Guy's display can close.
3. **The surprise class shifted from schema-FKs to filesystem/IO semantics.** Epic 4's mid-dev surprise was an FK (D3). Epic 5's CRITICAL + several HIGHs were all **path/IO semantics**: self-aliasing copy (5.4), atomicity of the swap (5.4), TOCTOU between validate and confirm (5.4), and `-wal` files in a sync folder (5.5). D3's "read the schema first" was the right instinct aimed at the wrong surface.
4. **The deferred-issue backlog rotted further and grew.** D4's five (#48/#49/#58/#60/#61) are *still* open, and Epic 5 added six more (#63/#65/#67/#70/#72/#74). The list is now growing faster than it is triaged — the same human-gated slippage as C1/D1, applied to product calls.
5. **Path-based UI as a stopgap created minor rework.** 5.2/5.3/5.4 shipped path-field controls "until the native picker (5.5)"; 5.5 then landed the picker and re-homed backups. Sequencing the picker earlier would have avoided the interim shape — though it kept the earlier stories unblocked, which was the right call under the dependency.

## 7. Key takeaways

1. **De-risk the seam first, and it pays off downstream** — the 5.2 export envelope (schema_version + integrity hash + version gate) was reused verbatim by 5.3 and leaned on by 5.4. D5 was the highest-leverage action item of the epic.
2. **3-layer review keeps earning its place** — it caught a CRITICAL data-loss bug (5.4 self-restore) and a design-level identity desync (5.1) that green tests could not. Keep it the default on every story.
3. **The surprise class moves; generalize the read-first habit** — Epic 4 it was schema FKs, Epic 5 it was filesystem/IO semantics (self-alias, atomicity, TOCTOU, `-wal`). Read the *whole* failure surface first, not just the schema (E3).
4. **A human-gated item that isn't a standing gate re-accrues every epic** — on-display GO/NO-GO (D1) and the product backlog (D4) both slipped again. Make them recurring per-epic gates (E1/E2), not one-off action items.
5. **Let the dependency gate steer the dependency choice** — `cargo deny` turned a security-advisory trap (printpdf/lopdf) into a clean pivot (pdf-writer) with no exception. The gate is a design input, not just a check.
6. **A feature can leave the architecture cleaner than it found it** — 5.6 relocated the construction path to `report` and made form-vs-PDF drift structurally impossible. Watch for these dividends and take them.

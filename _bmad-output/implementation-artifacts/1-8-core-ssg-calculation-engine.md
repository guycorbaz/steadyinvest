## Story

As the developer (Guy, solo),
I want the deterministic five-section SSG engine,
so that a study's canonical inputs produce the exact SSG output set, quality flags and verdict.

## Acceptance Criteria

1. **A pure engine exists in `core::ssg`**: `compute(financials: &CanonicalFinancials, judgment: &JudgmentInputs, observations: &QuarterlyObservations) -> SsgOutputs` (naming may vary per conventions; the quarterly/TTM observations are a distinct third input — they are market facts, not judgments), deterministic (identical inputs ⇒ identical outputs, FR4/FR29), **no I/O / UI / SQL / network** (Cardinal Rule), all math in exact `Decimal` (never `f32`/`f64`), **no rounding anywhere mid-chain** (display-only, `core::rounding`), and **no panic on any input**: every division via `checked_div`, every exponentiation via `checked_powd` (or guarded), and the **spec §9 degenerate-base guard applied BEFORE any `powd`/`ln` call** (Spike C: `checked_powd(-2, 0.5)` silently returns a wrong real number — the guard, not `checked_*`, is the protection). Currency is the caller's: outputs are in whatever native currency the canonical inputs carry (FR5); `core` does no FX.
2. **§1 Growth**: historical **sales CAGR** and **EPS CAGR** by the endpoints method over the usable years (first/last usable year, n = calendar-year span; n = 0, start ≤ 0, end ≤ 0 or sign-crossing ⇒ `unknown`, never 0 — spec §9); **recent quarterly % change** for sales and EPS (`(latest − year_ago) / year_ago × 100`, year-ago ≤ 0 or absent ⇒ `unknown`) from the optional quarterly inputs this story defines; **estimated high/low EPS**: a direct `estimated_high_eps` judgment value wins; else it is derived as `latest_usable_eps × (1 + g_eps)^FORECAST_HORIZON_YEARS` (exact integer-power projection; base = the EPS of the most recent usable year; base or `g_eps` absent ⇒ `unknown`) — same direct-wins pattern as 1.7's PTP gross-up. `estimated_low_eps` is **direct-only** in v1 (a low-EPS judgment is not a growth projection; absent ⇒ `unknown`). Both rules go in the Task 7 interpretation issue.
3. **§2 Management**: per-year **PTP %** (`pre_tax_profit / sales × 100`) and **ROE** (`eps / book_value_per_share × 100`); **5-year averages** = arithmetic mean over the **last 5 usable years** whose ratio is defined; **trend** (up/even/down) using `trend_even_band_pp()` (±0.5 pp vs the 5-yr average). `sales ≤ 0` or `book_value_per_share ≤ 0` ⇒ that year's ratio `unknown` + `negative_or_zero_denominator` finding, excluded from average/trend (spec §9; note: the spec defines this key only for EPS/book-value denominators — extending it to `sales ≤ 0` is an interpretation, Task 7 issue).
4. **§3 P/E history**: per-year **high/low P/E**, **% payout**, **% high yield** over the last 5 usable years; **averages** (avg high P/E, avg low P/E, avg P/E = mean of those two, avg % payout, **avg % high yield**, avg low price — the high-yield average is what §4 option (d) divides by); **current P/E** = `current_price / ttm_eps` where `ttm_eps` = Σ of the 4 quarterly EPS inputs (TTM EPS ≤ 0 or absent ⇒ current P/E, relative value and `relative_value_high` all `unknown`, spec §9); **relative value** = `current_pe / avg_pe × 100`. Per-year EPS ≤ 0 ⇒ that year's P/Es and % payout `unknown` + `negative_or_zero_denominator`, excluded from the averages; per-year `low_price ≤ 0` ⇒ that year's % high yield `unknown` + same finding, excluded from its average. Computed PTP/ROE outside `[−ptp_roe_bound_pct(), +ptp_roe_bound_pct()]` or P/E outside `[pe_axis_min(), pe_axis_max()]` ⇒ `out_of_bounds_ratio` finding, raised in the module that computes the ratio (`management.rs` for PTP/ROE, `valuation.rs` for P/E); value still reported — plausibility never blocks.
5. **§4 Risk & reward**: **forecast high** = `judged_avg_high_pe × estimated_high_eps`; **forecast low** per the 4 options (a) `judged_avg_low_pe × estimated_low_eps`, (b) average low price of last 5 usable years, (c) user-supplied recent severe low, (d) `present_full_year_dividend / (avg_high_yield_pct / 100)` (the §3 5-yr average high yield — interpretation, Task 7 issue) — option (d) **not selectable** when avg high yield ≤ 0 or `unknown` (spec §9 ⇒ `unknown`); **zones** = exact thirds of `forecast_high − forecast_low` with the spec's normative interval bounds (Buy `[low, low+third]`, Neutral `(low+third, low+2·third]`, Sell `(low+2·third, high]`); **present-price zone** (current price outside `[forecast_low, forecast_high]` ⇒ zone `unknown`; `current < forecast_low` additionally raises `low_price_above_current`); **U/D ratio** = `(high − current) / (current − low)`, denominator ≤ 0 ⇒ U/D **undefined** (typed state, never a number, never a panic — spec §9). Degenerate range (`forecast_high ≤ forecast_low`) ⇒ zones/U/D `unknown`, never inverted bands.
6. **§5 Five-year potential**: **present yield** (`present_full_year_dividend / current_price × 100`), **average annual EPS** over the horizon = mean of the projected yearly EPS (exact integer powers), **average annual dividend** (`avg_annual_eps × avg_payout_pct / 100`), **average yield**, **projected appreciation %** (`(high − current) / current × 100`), and **projected total annualised return %** = annualised appreciation **expressed in percent** (`((high/current)^(1/horizon) − 1) × 100`, §9-guarded fractional `powd`) **plus average yield %** (gross dividend — both terms percent before summing). `current_price ≤ 0` ⇒ all §5 outputs `unknown` (interpretation — no §9 row covers it; Task 7 issue).
7. **Flags, findings, confidence**: the engine raises the **quality flags** from the pinned `QUALITY_FLAGS` catalog using ONLY existing `core::method` constants (`ptp_trend_declining`, `roe_trend_declining`, `roe_low`, `eps_lags_sales`, `projected_high_pe_aggressive` (> 20), `projected_high_pe_implausible` (> 25), `ud_below_target` (< 3.0), `ud_extreme` (> 15.0), `relative_value_high` (≥ 100) — normative comparators, spec §7). **A flag is never raised on an `unknown` metric** (unknown ≠ a comparison result): this holds for `relative_value_high` (spec §9), `eps_lags_sales` (either CAGR unknown), `roe_low` (latest ROE unknown), both trend flags (average undefined), and the U/D flags (U/D undefined). `high_debt` is **not raisable in v1** (no debt field exists in `CanonicalFinancials`) — documented + GitHub issue, NOT a silent omission. The three **calc-time plausibility findings** (`out_of_bounds_ratio`, `negative_or_zero_denominator`, `low_price_above_current`) are raised as typed keys mapping 1:1 onto the pinned `PLAUSIBILITY_RULES` strings, **distinct from quality flags** (FR7 vs FR10). The output carries a queryable **`low_confidence` state** iff `usable_years < USABLE_YEARS_FLOOR` (FR8) — computation still runs on available data, never a hard block.
8. **Verdict facts (neutral, NOT `FullVerdict`)**: the output exposes the present-price zone and the four quality-candidate criteria as **facts** — U/D ≥ `ud_target()`, relative value < `relative_value_ceiling_pct()`, present price in the Buy zone, projected appreciation ≥ `verdict_double_appreciation_pct()` — each criterion tri-valued (met / unmet / **unmet-by-insufficiency** when its input is `unknown`, spec §9), plus the combined candidate fact. No recommendation, no banned verb in any string the engine emits (FR13 posture); the integrity-gated `FullVerdict` type (validation/freshness) is **Story 1.11**, not here.
9. **Property + metamorphic tests hold** (proptest + explicit cases, `core/tests/`): **zones ordered** `forecast_low < buy_top < neutral_top < forecast_high` whenever the range is positive (NFR-C3); **U/D ≥ 0** for current price within `(forecast_low, forecast_high]`; **determinism** `compute(x) == compute(x)`; and the **Story 1.7 handoff completes through the engine**: IFRS/GAAP-equivalent inputs ⇒ identical `SsgOutputs`; split-applied inputs (declared event) ⇒ identical `SsgOutputs`; scale-homogeneity — **all** monetary inputs ×k, i.e. the canonical series AND the monetary judgment/observation inputs (`estimated_high/low_eps`, `current_price`, `present_full_year_dividend`, `recent_severe_low`, quarterly sales/EPS), while dimensionless inputs (judged P/Es, growth %) stay fixed ⇒ ratios (CAGR %, PTP %, ROE, P/Es, U/D, relative value, zone classification) **unchanged** and price-dimensioned outputs (forecast high/low, zone bounds) scaled by exactly k (exact-by-construction inputs so `assert_eq!` holds with zero tolerance — see Dev Notes precision trap).
10. **Method discipline intact, gates green**: no constant in `core::method`/`quality_flags`/`rounding`/`method_version` added or changed ⇒ **no `METHOD_VERSION` bump**, `method_fingerprint_is_pinned_to_version` and `determinism_hash_matches_cross_os_contract` (+ the Spike-C pinned digest) pass UNCHANGED. `cargo fmt --all --check`, `cargo clippy --all-targets --all-features --locked -- -D warnings`, `cargo test --all --locked`, `cargo deny check` all green. Every spec-underspecified interpretation this story makes is recorded as a **GitHub issue** (repo `guycorbaz/steadyinvest`), never an inline debt note.

## Dev Notes

### The architecture this story completes — engine over 1.7's canonical layer

The pipeline is `normalize(RawFinancials) -> CanonicalFinancials` (done, 1.7) → **`compute(&CanonicalFinancials, &JudgmentInputs) -> SsgOutputs` (this story)**. The engine consumes the canonical output as-is: years sorted ascending, splits already rebased, PTP already canonicalized (§2 gross-up done — do NOT re-derive it), `usable_years` already counted, input-shape findings already attached. The engine adds the **calc-time** half: ratios, projections, zoning, flags, verdict facts. It must NOT re-run any 1.7 check (no split detection, no currency/fiscal checks) and must NOT take `Result` — the caller resolves `NormalizeError` before computing. [Source: core/src/normalize/{mod,types}.rs; 1-7 story]

### Type boundary unchanged: core does NOT depend on contract

Same rule as 1.7: `core` deps stay `rust_decimal` (+maths), `serde` (unused by ssg types in this story), `sha2`. `JudgmentInputs` is a plain `Decimal` struct whose names mirror `contract::Judgment` (`estimated_high_eps`, `estimated_low_eps`, `judged_avg_high_pe`, `judged_avg_low_pe`, `forecast_low_option`, `current_price`) and `core::method::LOAD_BEARING_JUDGMENT_INPUTS` — glued by the mechanical subset-test pattern 1.7 established, not by import. The contract→core mapping (Cell unwrapping, Money parsing, provenance) is the caller's job (app in Epic 2). Note `contract::Judgment` has no growth-% fields: the judged growth rates are engine inputs (FR6) whose *resulting* estimated EPS are what the contract persists as load-bearing — derivation is deterministic so the persisted values remain the source of truth. [Source: contract/src/study.rs; core/src/method/mod.rs; 1-7 story "Type boundary"]

### The `powd` discipline — Spike C's findings are binding

Measured on `rust_decimal` 1.42 (Spike C, 2026-06-11): bare `ln(0)`/`powd`-overflow **panic**; `checked_powd`/`checked_ln` return `None` on those; **but `checked_powd(-2, 0.5)` silently returns `-1.4142…`** (computes `sign(x)·|x|^y` — mathematically complex, a plausible-but-wrong number). Therefore the **§9 guard runs BEFORE the math**: CAGR and annualised return require base ratio > 0 (`start > 0 && end > 0`; `current > 0 && forecast_high > 0`) — the engine must never reach `powd` with a non-positive base. Integer-power projections (`(1+g)^5`) are **exact**; fractional powers carry ≤ ~1e-27 relative error — both fine. Use `checked_powd` anyway (overflow protection on extreme inputs). The 14 Spike-C tests regression-gate all of this — they are the engine's safety net, leave them untouched. [Source: docs/spikes/spike-c-decimal-cagr-determinism.md; deferred-work.md 1-1/1-2 items "checked paths land with the engine in Story 1.8"]

### Spec §9 is the engine's hardest requirement — every row is a test

The degenerate-input table (spec §9) was written FOR this story. Implement each row exactly: U/D denominator ≤ 0 ⇒ undefined (typed state) + `low_price_above_current` when strictly below; CAGR base ≤ 0/sign-cross ⇒ unknown; TTM EPS ≤ 0 ⇒ current P/E AND relative value AND `relative_value_high` all unknown (the flag is not raised on unknown — "unknown" ≠ "≥ 100"); per-year EPS ≤ 0 / book value ≤ 0 ⇒ year excluded from that average + `negative_or_zero_denominator`; option (d) with high yield ≤ 0 ⇒ not selectable. The verdict-facts layer then implements "unmet-by-insufficiency": an unknown criterion makes the candidate fact NOT met while staying queryably distinct from a measured miss. Never a silent 0, never a panic, never `Some(wrong_number)`. [Source: docs/method/ssg-method-spec-v1.md §9]

### Precision trap in the metamorphic suite — exact-by-construction or it flakes

1.7's lesson applies with more force here because the engine divides more. Scale-homogeneity ×k: `(k·range)/3` ≠ `k·(range/3)` in truncated `Decimal` when `range/3` is non-terminating (e.g. range 1: third = 0.33…3; k = 3: 1 vs 0.99…9). So for **zero-tolerance** `assert_eq!`: (a) construct generator values so divisions terminate (ranges divisible by 3, last-5 sums divisible by 5 — 1.7's "terminating-quotient strategy sets" trick), or (b) assert the **dimensionless/categorical** outputs exactly (CAGR %, P/Es, U/D, relative value, zone classification, flags) and the price-dimensioned ones on terminating-constructed inputs only. Do not paper over a mismatch with a tolerance — that hides real bugs; constrain the construction instead. [Source: 1-7 story "split handling — the exact-test trick"; core/tests/normalize_metamorphic.rs]

### Interpretations to make (and file) — the spec is deliberately thin here

Same pattern as 1.7's issue #12: implement a defensible reading using ONLY existing constants, record it in a GitHub issue for the next `METHOD_VERSION` bump, never edit the spec in-story. Known thin spots: estimated-EPS derivation (base = latest usable EPS; low-EPS direct-only — AC 2); option (d)'s divisor = the §3 5-yr average high yield (AC 5); trend = latest-usable-year vs 5-yr average (±0.5 pp band); endpoints-CAGR n = calendar-year span between first/last usable year (gaps compound across); `end ≤ 0` ⇒ CAGR unknown (zero is neither sign — rule it out explicitly); present price outside `[forecast_low, forecast_high]` ⇒ zone `unknown` (the spec defines zones only over the range); `forecast_high ≤ forecast_low` ⇒ zones/U-D unknown; §5 average annual EPS = **mean** of projected yearly EPS (spec allows middle-year as alternative — pick mean, deterministic); quarterly inputs assumed post-split/native-currency (the engine cannot re-check: quarterly data bypasses `normalize` in v1). [Source: docs/method/ssg-method-spec-v1.md §1–§5; deferred-work.md 1-2 "split_series_break precision" precedent]
